# v4 组合候选的离线行为诊断

H4 是离线评价方法。它不增加生产推理阶段，不把测试模板、样本身份或期望标签传给模型。当前样本保存在 `dataset/v4-behavioral-ai-draft/pairs.jsonl`：24 对、48 个输入，跨 systems、science、business、ordinary 四类内容。均为 **AI 起草、未获作者终审、已曝光的诊断材料**，不是人工金标，不是未见泛化主证据。

## 预先规定的变化

包括一致实体替换、保义改述、来源重排、无关材料、唯一必要前提删除、小数点／符号／整数变化、否定、条件、跨段共同前提、回答标题及换行边界、虚构设定与通常知识冲突、建议中嵌入事实前提。每对保存自己的前置理由、原／变体期望标签和证据段落索引。来源重排若涉及答案自身声称的 `Passage 0` 等归属，答案中的索引也按同一来源身份重映射。

“删除必要前提”仅在余下文字既不能支持也不反证时规定 S→U；数值、否定与条件变化只有构造了直接反证时才规定 S→C。不会把所有文字改动都预设为反证。当前回答边界家族通过标题／换行的表面变化保留命题含义，**没有评价同一字节串下人为重分定位单元**；后者需要独立的分区测试。

## 两种相同输入下的控制

- `end_to_end`：直接走被测后端的原生 `verify`，包含 M1、初判、既有有界复核与修复。
- `fixed_claim`：评价脚本仅对该次 verifier 实例替换 `_decompose`，供给预先写好的一个事实目标；随后走同一后端正常 M3 路径及复核。其成本不含 M1，不能与端到端成本混为一谈。该目标也是 AI 草案，不冒充人工事实清单。

每例预先声明一个事实目标，运行时不读取标签或家族来挑选 Prompt。模式内的规则及资源配置一致。`fixed_claim` 供给的只有目标文本和原回答定位元数据；两种模式都不向推理传递 fixture ID、家族、领域、关系或期望标签。

## 评分及分母

1. 完整输出的回答级诊断标签按 C 优先于 U、U 优先于全 S 聚合。空声明输出单列为 `NON_FACTUAL`，不得当作全 S；当前事实目标样本因此记错。
2. 部分输出仍记录有效 C/U 是否检测到问题；完整三分类标签记为未知，因为未完成声明可能改变其聚合标签。未知、失败、空输出均不会从总例数和总对数分母消失。
3. 同标签家族的“关系一致率”只测二者标签是否相等；**稳定地判错也可能一致**。同时报告每个输入的期望正确率、每对两项同时正确率和稳定错误对数。预设转移家族要求实际方向与两端预设标签一致，任意翻转不算通过。
4. 另外展示预设目标的文本对齐覆盖率、已对齐标签正确率、已知提取声明的完成覆盖率、未知声明总数的案例数、所需证据索引出现率、延迟及 token 成本。文本对齐不是语义召回证明；证据索引出现不是完整语义支持证明。
5. 两后端逐例比较已完成标签的错→对、对→错、翻转，执行失败→正确、正确→执行失败另列。这里的“对错”仅依 AI 草案口径，不能称为作者裁定结果。共同运行四个假设只能检验组合效果，不能归因到单个模块。
6. 固定目标模式逐次审计 C/U 复核的错→对、对→错、未变、错→另一种错及执行失败。审计仅针对实际触发的复核，后端间触发分布可能不同，不能解释为 H3 的独立因果效应；端到端的任意拆分声明不直接套用整例标签。

## 可复现运行

```powershell
python scripts/benchmark_v4_behavior.py --output-dir results/v4-combined-behavior --v4-config configs/optimized-v4.0.json --workers 4
```

默认在旧 v4.0 与组合候选上各跑两种模式，共 192 次请求。输出目录必须不存在，脚本拒绝覆盖；支持显式指定后端、模式和 `--limit-pairs` 做诊断，但不授予未见状态。费用只有显式传入同一组 input/cached-input/output 每百万 token 参考价格时才估算，否则保留 token 与缺失价格说明，不查询账单、不伪造当前价格。

首次调用前归档全部推理／评价 Python 源码及哈希、原始 fixture 文件及哈希、公开模型设置、阶段配置、所选 pair ID、比较后端和模式。加载、归档时分别检查数据哈希一致。运行保留模型返回文本、模型名及 fingerprint（供应方返回时）、调用轨迹、usage、错误、完整报告和评分。全程不归档密钥。结束再次检查源码是否改变；若改变，标记 `invalid_source_changed`、保留原始记录、拒绝发布有效评分并以错误退出。此程序不挑选或读取新的 RAGTruth v2 数据。

根据这些草案结果修改系统后，同样本继续只算开发诊断。新确认集仍需另行冻结、预先规定语义与采样，再作未见评价。本批样本的标签若有问题，保留原记录和版本化修订，不为提高结果就地改金标。
