# optimized-v4.0: author decisions and implementation record

These decisions were supplied by the user on 2026-10-22 (Asia/Shanghai). They supersede the proposed architecture where they differ. This file records requirements, not completed acceptance or human adjudication of data.

1. No finalized generic prompt text was supplied or found in the current project/history. Create and hash a new v4 prompt baseline from these decisions; do not claim recovery of an unavailable earlier draft. Use entailment definitions, citation discipline, and evidence before verdict. Instructions and advice themselves are non-factual; factual premises embedded in advice remain claims. An implicit claim can be supported by an explicit one-step inference from cited premises; without that inference it is unsupported.
2. Remove the runtime merge stage in v4. M1 alone determines atomicity. In the same sentence, a portion that only restates another portion in different words/symbols and adds no assertion can remain one claim. No connector lexicons, formula-specific runtime branches or programmatic sentence merging. Retain historical v3 separately as a comparator.
3. M1 chunks long answers by length with exact global coverage accounting. Each chunk receives bounded repair. On exhausted chunk extraction, deterministic sentence boundaries produce provisional claim skeletons, recorded as fallback; downstream semantic verification must not treat the skeleton's extraction as certified. M3 independently batches claims under a token estimate budget. Configure thinking and output limits separately for extraction, verification and review, recorded in every run/freeze. No failure may silently become UNSUPPORTED.
4. Quote repair: unique exact content at a wrong index, or provably content-preserving formatting differences, may be repaired without rejudging. Only a conservative safe subset of whitespace/quote/punctuation/NFKC normalization is permitted: never fold letters or numbers or meaningful mathematical operators. Fuzzy/content-changing matches are candidates for a targeted new semantic judgment, never silently substituted. The 5/7 recovery target means a finally complete valid report, including rejudgment. Content edits misclassified as format fixes must be zero in the acceptance sample.
5. Review order: initial verdict -> C review if C conflict is invalid (or a deterministic numeric conflict signal requests reconsideration) -> U review if the resulting verdict is U and U review has not been used. At most one C review and one U review per claim. U review may return C, but must supply a valid conflict in that same response; no subsequent C review. Format retries are independently bounded and counted. Record the entire verdict chain.
6. Keep /verify. Complete success retains {claims: [...]}. Partial success returns HTTP 200 with {claims: [...], status: "partial", errors: [...]}; each error identifies an unfinished claim and its reason. No completed claim means the existing error response, except genuinely empty/non-factual answers. Partial native detection: any completed C/U means positive; only S plus unfinished claims means unknown (neither TN nor FN). Report unknown, execution failures and completion coverage independently. Completed-only claim metrics require explicit coverage. Preserve legacy whole-case-failure scores as a separately labelled comparison.
7. Old RAGTruth blind-v1 180 cases are v4 development/regression data. The 7 bad quote cases belong to minimal. New v2 selection uses the same hash ordering with a seed containing v2, 10 sources per task / 30 sources / 180 responses, excluding every exposed source (including the old 30 and recorded smoke sources). Freeze inference/prompts/config before selection; separately bind data after preparation. Do not describe different slices as paired case comparisons. Physics/systems author-written or AI-drafted/author-final-reviewed sets are supplementary; never claim author approval without an actual decision. Do not delay principal external evidence merely for supplemental data.
8. Build versioned adjudication of claims reported in old minimal/v3 native-FP cases, explicitly distinguishing AI review from author review. No 'true FP' acceptance claim before the adjudication gate is satisfied. Target under adjudicated dev labels: true FP below minimal and no greater than v3; FN zero. Test native FN target zero, with a separately reported FP adjudication sample that never overwrites native labels. Minimal's historical successful-output FN=0; v3's is 1. These are measured targets, not guarantees. Unknown/failed outputs cannot be used to manufacture zero FN.
9. Numeric code is limited to already aligned anchors with identical literal unit strings. Extract value/unit pairs and emit a numeric-conflict signal when values disagree. It may trigger C review, never assign a verdict. No unit conversion, arithmetic solver or symbolic algebra in this iteration.

Implementation preserves the documented 64-claim response capacity; exceeding it is an explicit capacity error, never silent truncation. Input context remains a string array; structured source serialization is deterministic in the adapter and versioned there.
