# 四个假设组合实现：实测结果与结论

**已落地并完成比较，但本轮没有获得整体优化。** 组合版明显提高了报告完整率，代价是更多原生误报、约两倍参考费用和更长延迟；物理回归及行为诊断也没有显示整体优势。保留 `optimized-v4-combined` 作为可复核的实验后端，原 v4 和现有默认别名保持原有含义。

## 本轮做了什么

H1 将原答案定位、目标命题、答案背景和残留记账分开；H2 使用版本化证据指针，区分考察证据与判决证据，再从原文生成引文；H3 在现有次数上限内隐藏初判进行复核。H4 是离线行为与变形评测，不是额外的生产推理阶段。运行时没有按数据集、样本 ID、生成器或金标选择规则；没有增加运行时语义合并。

实现提交为 `18614f7`；上游 JSON 模式兼容修复后冻结为 **`07d6034`**。最后完整测试为 **377 passed**。原 v4 的推理、提示词、配置、引用处理和报告契约文件未改动，历史 v2 冻结检查通过。

完成三组实际比较，共 **644 条评测记录**：RAGTruth 180×2，行为诊断 48×2 后端×2 模式，物理回归 46×2。均使用同一个冻结版本与 v4 阶段配置；没有在看到语义分数后修改 Prompt、规则或标签。详细实现和调用前方案见 [组合实验说明](../../docs/V4_COMBINED_EXPERIMENT.md)。物理回归在行为结果之后登记为补充探索，登记早于其模型调用，见 [登记记录](../../results/v4-combined-20261023/physics-plan.json)。

## RAGTruth：工程完整性提高，原生检测与成本没有整体改善

使用此前已曝光的 `blind-v1/recovery` 全部 180 条，30 个来源组、每组 6 条；这是开发集，不是新未见集。两个版本按同一输入重新运行，逐例后端顺序由固定种子打散。全部 3,129 次调用返回 `deepseek-flash`，fingerprint 同为 `e72d3c7f663d3e1383b00b3884cb4501`。代码与数据在运行结束时均通过未变化检查。

| 指标 | 原 v4.0 | combined |
| --- | ---: | ---: |
| 完整 / 部分 / 整例失败 | 170 / 10 / 0 | 179 / 1 / 0 |
| 原生 TP / FP / TN / FN | 58 / 66 / 52 / 2 | 60 / 76 / 44 / 0 |
| 未决正例 / 负例 | 0 / 2 | 0 / 0 |
| 已决 F1 | 63.04% | 61.22% |
| 全 180 例上的正确决策 | 110/180 | 104/180 |
| 历史整例失败口径 F1 下界 | 56.98% | 61.22% |
| 已提取事实目标的完成率 | 1602/1619（98.95%） | 1812/1813（99.94%） |
| 模型调用 | 1509 | 1620 |
| 平均 / P95 秒 | 17.45 / 43.12 | 31.86 / 71.27 |
| 180 例参考费用 USD | 1.127709 | 2.395959 |

组合版完整率增加 **5 个百分点**，已决 F1 减少 **1.82 个百分点**，原生 FP 增加 10。参考费用为 **2.1246 倍**，平均延迟增加 **82.56%**，P95 增加 **65.25%**。历史失败口径随完整率提高而上升，不能用这一列替代语义检测比较。

按完整来源组做 2,000 次配对 bootstrap，combined 减去原版的 95% 描述区间为：完整率 **[+0.56, +10.56] 个百分点**，已决 F1 **[−5.67, +2.67] 个百分点**，全例正确决策率 **[−9.44, +3.33] 个百分点**。这是已曝光开发集的区间，不是独立泛化确认。逐例有 12 次原生错→对、19 次对→错，以及未决→对/错各 1 次。

**原生 FN=0 不能当作真实漏报归零的证明。** 对两条原生 FN→检测到的轨迹审查发现：`15485` 将操作建议抽为普通 claim 后判 U；`12297` 将 `(Passage 2)` 等出处/编号碎片抽为 claim 后判 U，其中推理本身称该片段没有事实内容。这些输出暴露了非事实分流和出处绑定问题，不能只凭回答级原生检测命中就叫修复成功。原始评分不改写；作者裁定口径的真 FP 与语义验收尚未完成。[数值与案例独立审计](dev-metrics-audit.md)

各任务的原生已决 F1 分别为 QA **40.91%→44.00%**、Summary **44.90%→40.74%**、Data2txt **83.52%→82.61%**，没有各任务一致改善。[完整分母、成本和分任务结果](dev/report.json)

## 哪些机制发生了变化

- M1 最终降级块 **70→14**，保留的句子骨架 **562→32**。组合版额外做了 85 次残留提取，其中 72 次清空文字记账，13 次仍需原句降级；另有 1 块初判失败。文字清空不证明事实完整，更多完成 claim 也不等于召回提高。
- 格式修复 **146→37**、批重试 **19→0**、定向重问 **184→119**。但组合版仍有 **105 次**因 U 的判决证据非空而重问；证据角色分离没有让模型自动遵守协议。
- U 复核 **316→467**，标签翻转 **36→150**。缺少逐条 claim 真值时不能把翻转数当纠错数，也不能单独归因于 H3。总输入 token 约 **248 万→579 万**，总输出 token 约 **80 万→161 万**，抵消了部分格式重试减少的收益。
- 最终唯一部分报告是 `6142/c10`：初判、定向重问、格式修复连续写错协议版本常量，其余 13 条 claim 完成。它按错误保留，没有静默变成 U。C/U 次数、顺序、共享定向重问和残留次数审计均未越界。
- 两版公开引文逐字有效性均为 100%（2213/2213 与 3630/3630）。这是位置契约，不是证据语义充分性；来源编号解释和计算错误仍能通过结构检查。
- 旧 7 条坏引用案例在本轮对照中，原 v4 为 6 条完整、1 条部分，组合版为 7 条完整。这项恢复检查仍属于已曝光开发验收。

上述为观测到的机制与开销，整套组合实验不能识别每个模块的独立因果收益。[完整结构审计](dev-operational-audit.md)

## 物理回归：严格对齐退步主要涉及表述，但也有真实判决错误

同一冻结版本在既有 CPHOS 46 例、58 条目标上重跑两个后端，均为 46 complete、0 partial、0 error。

| 指标 | 原 v4.0 | combined |
| --- | ---: | ---: |
| 严格文本对齐的已完成标签正确率 | 53/53（100%） | 44/45（97.78%） |
| Gold 文本对齐覆盖 | 53/58（91.38%） | 45/58（77.59%） |
| 全 gold 严格对齐 F1 诊断 | 89.08% | 73.33% |
| 输出 claim 数 | 61 | 62 |
| 平均秒 | 3.34 | 3.98 |
| 同一参考价补算 USD | 0.028771 | 0.045940 |

组合版 13 条未匹配目标中，11 条涉及改写、空格或翻译，2 条涉及拆分复合目标；还观察到重复输出。不能把严格 F1 的全部下降解释成语义准确率下降。

同时存在一处明确的计算误判：`q1-05` 中表达式实际为约 `0.0809895445`，四舍五入为 `0.081`；组合版算成 `0.085` 并给出 C。其结构化 conflict 和真实引文仍通过检查。独立算术复核只用于离线审计，没有加入运行时公式求解或案例规则。[物理只读分析](physics-readonly-analysis.md) · [全部指标](physics/report.json)

## 行为诊断：没有显示组合优势

24 对 AI 草拟原/变体、48 个输入；分别跑端到端和固定 claim 控制。192 条结果全部完整。

| 模式 | 原 v4.0 正确 | combined 正确 | 原/变体双项正确 |
| --- | ---: | ---: | --- |
| 端到端 | 48/48 | 47/48 | 24/24 → 23/24 |
| 固定 claim | 48/48 | 47/48 | 24/24 → 23/24 |

两种模式错在同一输入：`Passage 1` 的零基/一基解释不一致。保持草案原评分，同时注明自然语言编号歧义，不能把它说成两个独立错误或毫无歧义的通用败例。代码正确回填了模型选中的位置，初判 S 未触发复核；它不证明 H3 把正确答案改错。[来源解释审计](behavior-readonly-analysis.md)

固定 claim 两边各有 9 次复核，全部标签不变，净纠错为 0。端到端还出现来源归属丢失、主体只留在背景或代词未消解等现象，说明最终标签正确也不足以证明 M1 保真。全部期望标签均为 AI 草案，不冒充作者终审或未见证据。[行为计量审计](behavior-metrics-audit.md) · [行为结果](behavior/report.json)

## 失败尝试、验收边界与后续选择

首轮行为运行因新核查提示漏写 `json` 一词，被上游 JSON 模式以 HTTP 400 拒绝。停止时保留 165 条记录；通过一次直接请求确认错误后，仅补上明确的 JSON 输出指令并新增 JSON 模式兼容测试，随后在新目录重新冻结运行。原始失败记录未覆盖，也没有因不利语义分数重跑。已记录的有 usage 调用参考费用为 USD 0.039811；被中止的在途调用可能未记全，因此这不是该失败轮次的完整账单。[失败记录](../../results/v4-combined-20261023/behavior/ABORTED.json) · [上游诊断](../../results/v4-combined-20261023/transport-diagnostic.json)

本轮完成了“把四个假设组合落地并观察效果”，结论是**可以确认结构完整性的收益，不能确认整体语义或泛化收益，当前成本取舍也不理想**。后续更合适的工作是拆开模块作等预算对照，并优先检验 M1 的非事实分流、完整命题保真和背景绑定；复核则需同时衡量新增 token 与净改错。每项修改仍需从通用任务契约解释，不能加入这些案例的专用规则。

正式未见 v2 尚未取数，作者审核剩余细节尚未导入为最终裁定版本。本轮没有跨模型、未见来源或跨数据集优越性的验收结论，也没有将实验后端设为默认。
