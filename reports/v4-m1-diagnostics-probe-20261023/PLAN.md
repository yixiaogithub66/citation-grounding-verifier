# M1 bounded diagnostic feedback: predeclared synthetic probe

This is an isolated AI-authored contract diagnostic, not unseen evaluation, human gold, native benchmark data, or a production change. No benchmark text or identifiers enter these 12 new cases. Hypothesis: deterministic coordinates accompanying the existing error help the model repair its own extraction after one invalid response. The validator and all acceptance rules remain unchanged.

Two arms use identical answer, original v4 decomposition prompt, seeded invalid assistant JSON, original repair prompt, stage settings and one logical `decompose_repair_1` call. `terse_existing` supplies the existing validation message. `detailed_diagnostic` adds at most 1200 characters reporting one failing row, its cursor and up to eight exact occurrence starts, or up to eight uncovered intervals. The budget is a fixed resource bound, not fitted. Diagnostics do not decide NF roles, skip covered occurrences, alter source strings, assign spans, merge claims or supply answers. No additional repair/fallback or M3 calls occur. Existing transport retries remain bounded and fully counted.

The 12 cases vary English, Chinese, French and Spanish wording; NF missing/excess repeats and order; claim exactness and order; omitted facts, conditions, numeric signs, and advice with a factual premise. All seeds must fail the existing validator before any calls. AI-authored source target spans, without author approval, are supplementary lexical retention checks only: coverage by claim source spans does not certify claim_text semantics, complete extraction or entailment. Their text is never added to the request beyond the ordinary answer.

Order alternates first arm by case (six each); each pair runs sequentially, at most four pairs concurrently. This reduces systematic order effects but does not create independent generations or eliminate provider/cache drift. One observation per cell is exploratory, not a powered improvement test.

Run `python reports/v4-m1-diagnostics-probe-20261023/probe.py check`, then review code/cases. `prepare` writes the cases, exact 24 requests and a freeze binding plan, helper, inference/scoring sources, prompts and public settings. `run` checks hashes/settings and refuses an existing journal. Review/freeze must precede model calls. Never reselect cases or modify either arm after observing results.

Report all 24 outputs, acceptance (12 denominator each), accepted results whose supplied factual source targets are all claim-covered, all per-case regressions, raw usage, missing usage/cache accounting, fixed-reference and cache-standardized cost, and timing. Raw final response text, model/fingerprint and transport telemetry are retained; provider private reasoning is not. Reference prices are inherited from the paired NF experiment, not claimed current pricing or a bill. Fixed one-repair counts cannot measure fewer initial repair triggers. If both arms reach the ceiling or gains are ambiguous, do not promote. Any later research on these examples must treat them as exposed. Even improvement here would require independent broader validation before production adoption and is not an end-to-end accuracy/generalization claim.
