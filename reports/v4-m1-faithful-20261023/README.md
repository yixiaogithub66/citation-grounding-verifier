# M1 声明保真单独实验：结果与采用判断

**已实现并完成 548 条配对评测记录。原生检测分数有改善信号，但完成率下降，并出现事实遗漏、条件和来源绑定丢失；暂不替换原 v4。** 本轮没有证明通用性提升，也没有修改默认后端。

实验后端是 `optimized-v4-m1-faithful`，只替换原 v4 的 M1 系统提示。新的提示要求每个目标都是原答案实际断言的命题，保留主体、条件、范围、来源和建议中嵌入的事实；相同 schema、跨度校验、分块与降级、M3 提示、引用修复、复核次数和配置保持不变。没有新增运行时合并、数据集分支或案例规则。

- 调用前方案：[V4_M1_FAITHFUL_EXPERIMENT.md](../../docs/V4_M1_FAITHFUL_EXPERIMENT.md)。推理冻结提交 **`42c9469`**，**388 项测试通过**。

- 既有 AI 草案行为集：48 输入 × 2 = 96 条；物理回归：46 输入 × 2 = 92 条。它们是补充诊断，未经作者逐条终审，不是未见集。
- 相同提取结果下，M3 初判及 U 复核的请求逐字一致已由脚本化故障注入测试核对；没有重复花费模型调用运行相同固定 claim 路径。
- 全部 **548/548** 记录保留，未按分数挑样本、重跑或改提示。源码、输入、配置、逐条请求绑定、引用和复核次数审计均通过。[运行审计](operational-audit.json)

每输入、每后端只采样一次。来源组配对区间是对已观测输出的重采样，不能估计模型重复生成方差。新未见 v2 没有选取；作者裁定的剩余细节没有导入或被 AI 审计替代。

## 分数不能解释的语义问题

本轮另行审阅全部检测或完成状态变化的配对输入，并定向检查旧普通 claim 与新非事实排除跨度相交的情况。后者只用于离线诊断；旧 claim 不自动成为金标，候选数不代表遗漏数，未入选部分未做完整语义清查。[变化案例审计](dev-semantic-audit.md) · [排除清单审计](dev-exclusion-audit.md)

- 原生 FN→检测到的 `15485`，新版把操作建议直接抽为事实并判 U。按已确定的任务口径，不能据此宣布可靠纠错。
- `5278` 把一个询问句抽成事实并判 U；`15127` 把操作说明中断言的界面映射和搜索功能一起排为非事实。后者两版仍可全 S，回答级标签看不到事实漏提。
- 部分复合目标在新版被整体判 S，但身份、出处或因果子命题没有充分支持。粒度变粗减少目标数不自动等于减少冗余。
- `7022` 原版检测到营业时间冲突，新版相同 fallback 目标中的关键声明因 JSON 失败未完成，其余全 S，最终是未决正例。
- `7036` 的主体／评论者归属在拆分后丢失，相关声明跨核查批次，最后引用了另一评论者的内容；整答检测方向不变仍会掩盖这一退步。

对 180 配对输入做完整序列化比较，42 对提取 claim 对象完全相同，其中 41 对实际进入初始核查；有 **6 对**在初始核查输入相同的情况下，最终检测或未决状态不同。它们不能被归因为提取目标的改善；后续随机判决、重试和执行路径仍会影响结果。[具体 ID 与核对方法](operational-audit.json)

上述解释是有原文轨迹的 AI 诊断，不是作者终审标签，不会重写原生分数。

## 费用、执行和证据边界

全轮 3,260 次调用尝试中，3,237 次有完整输入、输出及缓存用量；23 次缺失用量，均在主开发集（原版 7、新版 16）。有返回标识的调用均为 `deepseek-flash`，fingerprint 均为 `e72d3c7f663d3e1383b00b3884cb4501`；缺失响应不能假称已确认模型标识。

沿用登记时的参考单价 USD/百万 token：输入 0.30、缓存输入 0.006、输出 1.20。**全轮有用量部分合计 USD 2.160547，缺失部分未计；这不是完整总费用，也不是实际账单。** 主开发集有用量部分分别为 USD 1.098834 与 0.961322，不能据此给出完整费用节省百分比。冻结评分器保留 `estimated_amount:null, complete:false`；报告侧审计单独给出可计价调用的小计，不修改评分代码。

行为参考费用为 USD 0.021259→0.021659；物理为 USD 0.029702→0.027771，这两组用量完整，但包含单次缓存与输出差异。公开引文逐字有效性均为 100%，复核与共享定向重问次数未越界；这些检查不保证目标提取完整、来源绑定正确或证据蕴含成立。

## 结论与文件

保留此实验后端供复核，不升级默认。它显示来源保留和同句表达粒度有局部改善可能，也显示仅加强提示不能稳定阻止错误排除、限定丢失和事实化建议。后续更值得单独验证的是**非事实排除的语义漏检控制与条件／主体保真检查**，并计入额外调用成本；不能从这些案例提取专用关键词或补丁。
