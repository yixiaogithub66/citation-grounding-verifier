## 为什么换全局匹配算法不能直接解决这批剩余项

既有候选生成已经筛掉剩余五个目标的所有可用边。下面相似度沿用冻结实现的 `SequenceMatcher` 计算，仅用于解释该实现为何拒绝，不是新的阈值建议：

| 仍未匹配目标 | 当前文本候选情况 | 局限 |
| --- | --- | --- |
| `q3-05` G1 | 唯一输出相似度约 0.151，关键 token 一致 | 中英等价翻译的词面重合低 |
| `q4-01` G1 | 唯一输出相似度约 0.780，关键 token 一致 | 中文空格与短语次序变化，低于文本门槛 |
| `q5-03` G1 | 文字部分约 0.630、公式部分约 0.702；文字部分不含完整数学 token | 两条联合才对应复合目标 |
| `q5-06` G2 | 分母说明约 0.389，公式部分约 0.840；各单条均不通过完整关键 token 比较 | 一对多关系与重复；原句中的变量 `m` 出现次数也与拆分后不同 |
| `q7-05` G1 | 唯一输出相似度约 0.870，关键 token 一致 | 方法前缀省略；既有阈值外，还有未定的语义范围问题 |

因此，保持 admissible edges 不变时，匈牙利／其他全局一对一求解不会增加这五项的匹配。放松阈值、增加跨语种模型或组匹配会改变问题本身，必须有独立的对应关系校准和误配检查；不能按这五项的得分挑参数。

## 后续离线审计的建议口径

关系词仅作为审计类型，不改变运行时判决，也不直接替代历史评分：

| 类型 | 定义 | 如何计账 |
| --- | --- | --- |
| equivalent | 一个输出保留一个目标的全部事实内容与限定，双方可相互蕴含 | 可交人工确认对应，仍需单独检查标签与证据 |
| split | 多个输出联合对应一个目标，各输出仅覆盖其中一部分 | 显式列组与各部分覆盖；不重复计完整目标，重复输出另列 |
| merged | 一个输出包含多个目标 | 显式列被覆盖目标，并检查是否额外引入关系；不把一个标签自动传播给所有子事实 |
| partial | 只保留部分主体、条件、关系或内容 | 列出缺失内容；不升级为 equivalent |
| ambiguous | 至少两种合理语义解释，或无法唯一确定对应 | 保持未决，列出解释与人工确认需要 |
| unrelated | 无可辩护的对应关系 | 保留未匹配，不强迫分配 |
| duplicate（附加标志） | 输出重复另一输出已表达的同一事实 | 在所有关系之外单独计重复，不增加语义覆盖 |

本次 13 项没有明确发现 merged 或 unrelated，不代表系统不会产生这两类错误。关系审计应同时检查预设→输出的遗漏与输出→原答案的忠实性，避免“对齐了某个预设目标”掩盖模型凭空补入事实。

若后续实现自动化辅助，先固定不读取 verdict、reasoning、证据质量和 backend 身份的对应规则，并允许拒绝匹配。验证应覆盖数字、否定、条件、主体、来源归属改变，以及真正的同义改写、翻译和复合拆分；不能从本批样例抽取运行时例外。评估全局求解器时先保持同一候选边集合，才能区分求解策略与候选表示的收益。独立报告覆盖率、重复、未决、错配和额外输出，而不是只展示匹配后准确率。

## 解释边界

严格文本分数确实混入了措辞与粒度变化，因而不能把其下降幅度等同于语义能力下降幅度。但这也不能反推 combined 已经语义等效或优于旧版；本审计只覆盖严格未匹配现象，不认证其判决和证据充分性。旧报告中另外定位的计算误判仍然成立，重复输出也仍然存在。

RAGTruth 的原生回答级检测没有经过上述 claim 对齐，因此此次审计不解释、更不消除其原生 FP 上升。所有数据保持已曝光状态；任何依据本文进行的开发都不能在同批数据上宣称未见泛化改善。本文未生成调整后成绩、作者裁定文件或新金标。
