## 恢复是否可保留比较

可以继续这个探索性实验，但需明确作为基础设施恢复及原 no-resume 协议的一次偏离，不包装成无中断执行。必须保留原 50 条（包括全部 9 条 error），只执行冻结集合缺失的 102 个身份；不依据语义、valid/error、成本或臂别重跑、换样或选择输出。模型、Prompt、案例、金标、预算、validator、无 repair 规则及冻结源码均不变。

自然修订必须引用其原来的 base 草稿与 validator 状态；已有 base 不重取，未执行的 base 只取一次。generic 与 bidirectional 必须继续收到同一修订 payload。整体替换规则不变。恢复只是调度和持久化修补，不得在恢复文件中复写推理逻辑。

原已记录块各臂齐全，恢复后可按同一 answer/repetition 做配对比较；中断造成的时间段、缓存和负载差异仍需记录。不能把第一次与恢复阶段的 wall-clock 间隔记入正常模型推理延迟，也不能隐藏新增基础设施等待。

## 未追踪的一个预留必须如何披露

51 次预留对 50 条 journal，说明存在一个未归入可追踪响应的预留。现有证据不能确定它是否触达服务端、是否计费、属于哪个身份或是否已有未保存的响应。不得将它当作第 51 条有效结果，也不得将其写成确定零请求/零成本。

恢复完成后的准确口径应是“152 个计划身份各保留一条可追踪结果，另有原中断时 1 个不确定预留；可能存在至多 1 次额外未追踪请求”。如果每条可追踪记录都确认有一个 provider 调用，则可追踪请求为 152，实际请求总量只能在 152–153 范围描述；不能仍绝对宣称总共恰好 152 次实际 API 调用。若后续服务端或进程证据能消除该不确定性，可以追加证据更新结论，保留原记录。

原调用上限 152 可能被这个不确定预留突破一次，这是协议偏离。总费用是已追踪费用加未知项；不可将未知项默认为 0。各臂的已追踪费用可比较，但由于未知项未归属，实际全链计费的精确对比有这一限制。不要据未知预留的推定臂别调整评分或删配对块。

## 恢复实现的最低核对条件

1. 原目录与冻结源码保持字节不变；新恢复目录先保存原 journal/progress/hash 与 traceback，另存恢复方案和恢复程序哈希。
2. 从冻结 expected_identities 计算缺失身份，拒绝任何重复、意外身份或新的非计划调用；已有所有 error 也算完成身份。
3. 恢复前逐一核验 Prompt、案例、源码和 settings；恢复程序调用冻结的 single_call、payload 构造及 validator，不复制修改其规则。
4. 每次新调用前持久化包含身份及 payload/prompt hash 的 reservation；结果追加并 fsync。进度文件采用不会因同目录临时替换失败而丢 journal 的策略，基础设施写失败不触发模型重试。
5. 再次中断遇到“已 reservation、无结果”时不得自动再发同身份请求；先明确标 unknown 并保留追踪证据。只凭无 journal 判断“没调用”并不总成立。
6. 最后核验全部 152 个预定身份恰各一条、原 50 条逐字保留、原有错误没有换成重跑成功，校验同 base 与同 payload 配对，并单列新增调用数 102 和不确定预留 1。

恢复前没有查看语义结果，使该动作不属于观察得分后选择性重跑；它也不自动恢复原始无偏执行声明。最终报告需同时陈述完整比较的可用性与这项基础设施偏离。
