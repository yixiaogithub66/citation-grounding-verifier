# 覆盖协议诊断与候选反证

2026-10-24。只读诊断；未查看本轮 `cases.json`，未改生产代码或候选 Prompt，未调用外部模型。依据为当前 `grounding/verifiers_v4.py:91`、`grounding/prompts_v4.py:11` 和上一轮已经曝光的 152 条响应。本文不把旧样本文本或词汇转成运行时规则。

## 当前契约究竟保证什么

`extract_claims` 强制严格字段、非空文本、容量限制、来源精确子串、来源出现顺序，以及 claims 和 non-factual spans 的范围并集覆盖所有实质字符。实质字符包括字母、数字、组合符号、符号及部分运算符。两个数组独立维护来源顺序；重复 non-factual 文本必须分别对应原文中的出现位置。

这能证明来源范围确实存在和字符已记账，不能证明 claim 忠实、原子、独立自足，也不能证明范围中的每项事实都已提取。合法的全句 source_span 已经可能覆盖多个未被 claim_text 表达的事实。反过来，已经正确提取事实仍可能因为未抄连接文字而失败。

`source_span` 是来源定位，并非 M3 的上下文证据引用。改变它的表示不能直接推出引用核查准确率提升。当前实验若只运行 M1，结果不能称为 `/verify` 完成率。

## 上一轮故障的进一步拆账

上一轮的 20 条结构失败均有正常模型响应：18 条字符覆盖缺口、2 条 non-factual 来源顺序问题。按原 validator 的出现匹配逻辑重建范围后：

| 类型 | 输出数 | 对本轮设计的含义 |
|---|---:|---|
| 仅遗漏连接、引导或组织文字，未见漏掉事实正文 | 17 | 此处存在额外字面记账负担；但不能据此建立连接词忽略词表 |
| 同时遗漏连接文字及一项完整事实 | 1 | 覆盖失败也能阻止真实漏提被当成完成；降低定位粒度可能掩盖它 |
| non-factual 片段逐字存在，但开头片段被追加到数组尾部 | 2 | 这是来源顺序失败，不能写成“精确复制失真” |

那一条真正漏事实的旧输出为 `sel-10 / fresh / repetition=0`：仅提取两个预设事实中的一个，另一项带来源归属的事实没有进入 claims 或 non-factual。这里保留 ID 仅供审计，不能传给候选推理或用于挑选新样本。旧报告“有效输出中没有观察到自然漏提”仍成立；“所有覆盖失败只是格式问题”不成立。

因此，本轮合理假设是：**明确寻址与单元记账可能减少与语义提取无关的完成障碍，但可能降低对遗漏的机械检出力**。必须同时测完成率和固定事实目标，不能只测 validator 通过率。

## 建议的最小协议及边界

输入由代码生成按原序排列的来源单元：`{unit_id, text}`；代码另存精确 `[start,end)` 偏移，不让模型生成偏移。原文保留全部内容、原序及格式，来源单元只是地址，不是原子事实，不可作为禁止跨单元指代或拆分的语义边界。所有单元按字符拼接应严格还原输入答案；若格式空白独立储存，也必须明确其范围。

一种最小输出可为：

```json
{
  "claims": [
    {"claim_text": "standalone assertion", "source_unit_ids": ["u0001"]}
  ],
  "unit_ledger": [
    {"unit_id": "u0001", "kind": "factual"}
  ]
}
```

`kind` 固定为 `factual / non_factual / mixed`。如果要保留当前 non-factual 理由，可统一增加非空 `reason` 字段，但理由是模型解释，不是确定性证明。`mixed` 表示同一来源单元兼有事实断言和建议等非事实言语行为，不等于允许省略其中事实。

机械检查至少包括：

- ledger 中每个输入 unit ID 恰好出现一次，无未知 ID、缺失、重复或隐式补全。
- claim 只能引用真实 unit ID，引用列表非空且不重复；每条 claim 保留同样的事实提取语义要求和容量上限。
- `factual` 和 `mixed` 单元至少被一条 claim 引用；`non_factual` 不得同时有 claim 指向它。后一约束要求区分“该单元断言事实”和“仅提供指代背景”：若实际协议允许独立背景引用，应另设字段，不能混用两种含义。
- 无 claims 时所有有内容单元都必须由模型明确标为 non-factual；缺失 ledger、未知类型、无法解析均为错误，不能自动转 NF。
- 代码从原文恢复 unit 的精确范围；若多个单元不连续，应保存多个真实范围，不能把拼接文本冒充原文连续子串。展示整单元来源也应标明其粒度，不能声称它是模型选择的最小事实跨度。
- 不将单元作为 claim、自动组合相邻 claim 或补写声明。来源地址的整理不是原子语义粒度的处理。

规则不应要求模型按顺序再次抄列 ledger 才算有效：只要 ID 完整唯一，代码可以按原序读出映射。若 copy 对照仍要求数组严格来源顺序，则该变化会与“省去复制”混杂，应在设计中拆开或明示。

## 为什么它不等价于旧覆盖契约

旧契约要求每个实质字符属于模型给出的精确来源跨度或精确 NF 跨度；新契约要求每个预先划定单元有一个类别，并给事实单元至少一个 claim 地址。给含多项事实的单元挂一条 claim 即可机械通过。这不是保持旧校验强度的纯序列化替换，也不是“自动修复了同一错误”。

把恢复的整单元 source_span 再送进旧 validator，容易机械覆盖整篇文本；这不能宣称两臂接受了同等原始要求。尤其 mixed 单元被分类后，其具体非事实措辞已不再逐字记账。报告应明确叫“单元覆盖协议”，而非证明“语义覆盖”。

单位切分自身也是干预。句号、换行等通用结构切分可以实现稳定地址，但缩写、编号、小数后的空白、表格行、引语、长句均可能产生意外边界。硬截长单元更不能被当成完整命题。模型必须能看全文或足够显式边界上下文；不得逐单元独立判断后丢掉跨单元条件或归属。切分规则在新结果前冻结，不依据领域或样本效果调整。

## 公平的最小对照

建议至少三臂，单次模型调用，模型、thinking、输出预算、并发、重试和语义规则一致：

1. 现有 M1 原 prompt + 原 validator，作为历史兼容和实际路径成本的描述性基线。
2. **unit-copy**：同一来源单元输入、同一 ledger、同一语义规则；来源定位要求输出对应单元的精确原文。
3. **unit-ID**：除了来源表示/必要 schema 说明，和 unit-copy 相同；输出 unit ID，代码恢复来源。

主机制比较为 unit-copy 对 unit-ID。原 M1 对 ID 的差异同时包括单元化、ledger、语义提醒和表示变化，不能全部归因于去复制。若 copy 臂用自由跨度、ID 臂用整单元，则更是粒度与寻址联合干预；仍可以做工程路径比较，但必须如此命名。

为保证重复文本定位公平，unit-copy 也应显式持有 unit ID，并额外抄写 text（即“ID + copy”对“ID”）；否则其仅靠重复文本匹配的歧义引入第二变量。这个设计检验“冗余复制负担”，不再单独检验 ID 是否优于纯文本寻址。两种问题只能选清楚，不能事后混说。

全部新样本先固定，不能筛选只让 baseline 失败者进入实验。可以事先覆盖多语言、纯 NF、混合语句、重复表述、指代、条件、编号等通用结构，但不要套用旧失败句模板或旧词汇。样本标签由未见输出的作者预先标注；AI 标注不冒充用户终审。

## 完成率、保真、成本必须联合解释

- 每臂所有输入重复为固定技术完成分母；完整返回但 ledger 无效依然失败。
- 每条预设事实机会为固定语义分母，技术失败记未完成，单列有效输出中的真遗漏。模型把多事实单元只提一条不能因为 ledger 完整就算通过。
- 纯 NF 和 mixed 中误纳建议均审阅；检查条件、归属、数值、否定、模态、主体和独立自足。完成率增加但错误 claim 增加不算全面改进。
- 建议额外人工/AI 审阅无效输出的可读 claim，以区分“不服务的正确事实”与“真正语义漏提”，但这些不能加入严格有效主分数。
- 统一单次调用比较，同时给 input/output tokens、固定无缓存参考成本、实际缓存口径、每个有效且保真的输出成本。输出省下复制 tokens 可能被输入的 ID/ledger 或更长 schema 抵消；不能先验宣称更便宜。
- 重复运行不是新的独立回答；比较要按输入配对，分开报告不同领域与语言。小批 AI 起草诊断材料的增益不构成跨真实数据集泛化证据。

本轮的可接受结论最多是：在冻结的新小样本上，某覆盖协议提高了技术有效率，且未观察到预先检查的语义保真回退，成本如何变化。生产接入、现有 `/verify` 兼容、降级链与真正未见真实来源验证均需要另做，不应被本轮 M1 结果自动授权。

## Gemini 设计意见后的精简方案复核

主代理拟采用 `ledger: [{unit_id, claim_ids, nf_reason}]`，取消 kind 枚举；copy 臂仅额外增加精确 `source_text`，ID 臂没有此字段。claims 通过独立 ID 被 ledger 引用，代码按关联最小单元的顺序稳定排序，不改变 claim 文本或集合；只输出精确离散 source_units，不构造包围跨度。

这比上文的三分类示例少一层重复约束，原则可接受。两臂必须共享同样的 ledger、排序和语义标准；ID+copy 对 ID 检验的是冗余复制负担。必需不变量仍为：每单元恰有一条 ledger；每 claim 至少关联一个真实单元；未知、重复或格式错误的 ID 明确拒绝；没有 claim 关联的单元必须由模型给出非空白 nf_reason；不得由代码把缺失账本补成 NF。claim_ids 与 nf_reason 同时非空不应额外触发类型冲突。

nf_reason 只是模型给出的非事实处理理由，不能证明其中没有事实。单元可能为某 claim 提供指代背景，并不一定自身独立断言新事实；同样不能从非空 claim_ids 推导“本单元的所有文字均为事实”。这些关系要在共享任务说明与语义审阅中统一解释，代码不增加语义猜测。

稳定排序应保留同一最小单元内的模型相对顺序，且不得对相同 claim_text 做语义或字符串去重。提取原子粒度仍归模型。新的 source_units 结构是研究输出，不能假设已与生产 M3 对单一 source_span 的所有用途兼容。

Gemini 把主对照称为可“严格归因因果效应”，措辞过强。它可以提供冻结设计下的一次小样本机制对照，但模型随机性、有限输入分布及未独立重复均限制外推。Gemini 建议的联合有效与语义指标合理；数值门槛需要主代理在推理前锁定，而不能当作外部权威给出的通用验收标准。
