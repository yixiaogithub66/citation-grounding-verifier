# 通用核查系统：多来源研究、Gemini讨论与小规模验证

2026-10-23～24。**本轮形成三个联合来源假设，实际验证两个；两者都未达到预登记的扩大验证标准，生产保持不变。** 最重要的收获是进一步区分了事实选择、证据蕴含与输出协议三类问题，并识别出单向NF审计的观测盲区。没有为获得正结果修改样本、标签或Prompt后重跑。

研究共整理22条一手来源记录：14篇论文相关记录、6份官方文档、2篇工业博客。不同资料的阅读深度和证据强度明确区分，并非22份独立实验或14篇全文精读。Gemini通过本机Antigravity CLI High参与两轮方案讨论和一次结果反证；我方负责检索、来源核验与最终取舍。完整过程见[研究范围](SCOPE.md)、[综合推导](SYNTHESIS.md)、[最终反证](FINAL_REVIEW.md)。

## 文献如何改变优化方向

| 联合来源 | 支持的机制判断 | 本项目的迁移边界 |
| --- | --- | --- |

本地证据与文献相互约束：combined提高完整率却没有整体语义收益；faithful-M1仍会漏事实、丢限定；small30中minimal与v4共同已决28条各17正确。这些事实支持分开实验，不能被某篇论文的正面结果覆盖。[本地诊断](local-diagnosis.md)

## 三个联合假设与取舍

**A：对合法NF排除做一次有原文见证的审计。** 将Claimify的覆盖观念与AFaCTA的事实性区分结合，假设可以找回建议中确实断言的事实；以同模型自改的负面证据约束它，增加fresh提取和离线集合对照。它区别于旧的“未覆盖文字补提取”，但仍只是待测的影子机制，不直接进入生产。

**B：一次核查中明确必要成分的证据责任。** 借鉴阅读理解策略和对齐研究，按主体/归属、关系方向、限定、一步蕴含核对，在原derivation字段指出关键证据或缺失部分。保持原标签、输出Schema和预算。这是提示强化小试，不宣称新架构首创。

**C：独立降低输出协议负担。** 当前客户端已经有JSON mode及安全引用修复，不能重命名为创新。DeepSeek的Chat与Responses文档支持不同的输出模式，后者列有json_schema，但本账户实际支持和语义影响尚未测试。本轮暂缓迁移API，避免再混入多个变量。[Chat文档](https://api-docs.deepseek.com/api/create-chat-completion/) [Responses文档](https://api-docs.deepseek.com/api/create-response/)

## Gemini的参与确实改变了设计

Gemini建议先测B，我方补充A。双方讨论后保留两个独立实验。我方否决了它第一轮“统一开启thinking 16384”的建议，因为当前初判是disabled/8192；也纠正了只对候选删证的设计和缺乏日志依据的截断猜测。

Gemini第二轮指出：base+审计保留旧结果再补漏，而fresh只替换旧结果，两者算子不同，会偏袒审计。因此增加了**base+fresh的离线事实目标集合对照**，不新增调用，不恢复运行时语义合并。重复事实按预设目标只计一次，错误新增单独计。来源、讨论和最终纠偏全部保留。[两轮方案综合](SYNTHESIS.md) · [结果反证及主代理纠正](FINAL_REVIEW.md)

## 实际小试结果

首次调用前提交`d7f81bc`并冻结代码、两份新案例、Prompt、PLAN与配置。7项本地测试通过。全部使用deepseek-flash、thinking disabled、8192输出预算、单次调用，无额外格式修复、降级、C/U复核或重问；因此是**初始阶段机制probe，不是完整v4端到端评测**。所有期望均为AI草稿，未冒充作者终审。[预登记](PLAN.md)

### P1：M3必要成分短核对

12条固定完整claim，6组关系/条件/同义/一步推导/删证对照；两臂各重复2次，共48调用。每个输入均出现在两臂，先后次序配平。

| 指标 | 当前初判提示 | 加短核对要求 |
| --- | ---: | ---: |
| 原始标签及推导语义正确 | 23/24 | 23/24 |
| 校验有效 | 22/24 | 23/24 |
| 有效且标签、证据与推导正确 | 21/24 | 22/24 |
| 共同有效的22对中正确 | 21 | 21 |
| 输入/输出token | 21,242 / 3,544 | 25,034 / 3,428 |
| 统一全未命中参考费 | $0.0106254 | $0.0116238 |

净多一次严格成功，来自U不再错误携带引文，没有新增原始语义纠错；无缓存参考费增加9.40%。两臂仍在同一条件例中把充分条件读成必要条件，输出了结构合法、引文精确但语义错误的C。正常同义、正向一步推导和删除唯一证据的案例未退步，但没有满足预登记的至少两次净改正及同一反例两次重复均改善条件。**不晋升。** [全部48条语义审阅](p1-semantic-review.md)

### P2：NF影子审计对照fresh提取

12条新回答，6个固定事实目标、6个纯NF对照，包含中英法西语。每条基础M1与fresh各一次；只有基础输出合法且NF非空才审计一次。共30调用、6次明确跳过。全部输出按预先写下的事实与禁提断言审阅。

| 观察 | 结果 |
| --- | --- |
| base / fresh合法输出 | 10/12 / 11/12 |
| base、fresh、base+审计、base+fresh的有效固定事实目标 | 均为5/6 |
| NF审计调用 / 新恢复 | 6 / 0 |
| 触发集合内可恢复的预设漏提正例 | **0：恢复召回尚未测得** |
| base / fresh纯NF正确 | 1/6 / 3/6 |

唯一未计入的事实目标落在初判文字覆盖失败，审计依法跳过；不是审计看见漏事实却无法恢复。其余实际触发例没有目标漏提。因此零恢复属于**没有恢复正例机会的无信息结果**，不能推成NF审计一般无效；但也没有理由现在增加生产调用。

新的诊断线索是：部分试探建议、行动指令或假设内容被放进了claims。单向NF追加审计没有入口删除这些误纳项。审阅区分“祈使句直接入claims”“新增能力断言”“删除假设范围”，没有把所有错误都叫现实世界虚构；一条保留想象范围的输出保留边界未决。**不晋升，不在本批例子上追试。** [36条记录逐项审阅](p2-semantic-review.md)

## 这次研究之后，优化优先级怎样调整

1. **优先定义并测试双向事实选择保真。** 不只查NF中有没有漏事实，还查每个已提claim是否真是原回答断言、是否将建议/假设改成了事实。依据来自Claimify、AFaCTA和本轮独立诊断；这是下一轮假说，尚未证明有效。应使用新材料，同时覆盖误删与误纳，并保留纯建议、正常事实和合法同义反例。
2. **把条件方向与来源归属作为语义失效机制，继续寻找可验证干预。** 本轮短提示没有解决充分/必要条件误读，不能再用更多重复提醒宣称进展。未来设计需证明跨重复净语义改正，且不以新增U、少提事实或过度字面化交换分数。
3. **序列化改进另开独立能力验证。** 先实测官方schema模式及必要字段回填能否降低协议失败，再评估语义与费用；绝不把这种工程收益当成准确率改善。现有安全修复继续保持内容边界，不折叠数字、字母或否定。

这些是研究优先级，不是已实施的生产改善。本轮的联合创新主要在问题拆分、审计对象和实验控制，尚无新算法或普遍收益证据。正式未见RAGTruth v2与作者裁定要求保持原样。

## 成本、核验和局限

实际78次调用，共69,181 token（60,315输入、8,866输出）；84条预定日志含6条skip。参考费$0.01605495，统一全未命中$0.02873370，均按此前固定单价估算，不是账单；Gemini研究会话开销单独记录。全部调用有用量与缓存账，返回模型和指纹一致。

机械审计重算84条身份、78调用、预算、请求白名单、冻结哈希和费用；38条公开引文与10条conflict引用逐字匹配，0次安全直修。生产未改，旧预测未改，未调用新的benchmark测试集。[运行审计](operational-audit.md) · [原始响应与机械分析](pilot-results/analysis.json)

案例短且AI草拟；P1重复不增加独立来源数，P2仅一次自然生成且语言与家族混杂。跨角色AI审阅不等于独立人审。未完成端到端验证或泛化确认，不能由本轮数字外推部署收益。曝光记录见来源清单，后续采用相关外部集合时仍须处理论文示例曝光。
