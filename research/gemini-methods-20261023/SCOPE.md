# 本轮研究范围与来源策略

2026-10-23。继续用户已明确指定的工程研究问题：如何在不针对 benchmark 特调的前提下，让当前 Citation Grounding/Faithfulness Verifier 更准确、可靠且经济。用户同时授权 Gemini 辅助、方法可行性讨论与小规模验证；本轮直接延续该范围，不重开研究方向确认。

采用 deep-research 的来源核验、跨来源综合和反证流程。这是任务限定的工程调查及机制试验，不是系统综述、论文复现或完整学术研究；不声称穷尽文献或首创方法。先检查本地已失败路线，再将论文机制和工业文档中的可行边界组合成可证伪假设。

## 问题及证据分层

1. M1 的合法 NF 排除是否在语义层漏掉事实？新审计能否超过同样多一次独立提取，而不把建议/假设升格？
2. 同一次 M3 内核对主体、关系和必要限定，能否在不改变预算与标签契约时减少语义错误？
3. 输出协议能降低多少执行故障？将已存在的 JSON mode、安全引文修复与尚未实测的严格 schema 支持分开。

本地日志提供本系统的故障事实；论文提供受其模型/数据/任务限制的机制证据；厂商 API 文档提供功能契约，博客提供厂商经验；本轮组合方案是待验证假设。各层不互相冒充。研究检索、方法建议、AI草拟样本和语义审阅均不等于用户逐条终审。

## 检索与筛选

检索日期为2026-10-23；没有人为只限于支持候选的年份。优先2024–2026相关新论文，保留与可证伪设计有关的较早一手研究。使用ACL Anthology、arXiv、会议出版页、作者/机构页以及DeepSeek、Google、Anthropic、Datadog、AWS官方资料。包含主张提取、分解反证、NLI、证据依赖、结构化输出、推理开销与重试放大；排除二手SEO、仅宣传数字、不能核实存在的引用，以及与闭卷核查契约冲突而无法独立测试的方案。

具体查询、阅读范围和不能推出的结论见 claims-sources.json、industry-sources.json、root-sources.json。检索返回的二手结果只作线索，不作技术论据。没有抓取新的benchmark数据文件；研究页内自动显示的样例单独记录，不进入Prompt或新合成案例。

## 协作与反证

- 主代理整合本地数据、核实引用、制定实验与作最终判断；并行角色负责论文、工业方法和本地反证。
- Gemini通过本机Antigravity CLI `gemini-4-argon-high`、`--effort high` 工作，仅读取内联核验材料。它参与综合和争论；没有自行联网，不能把它补写的引用视作已核验资料。CLI输出、状态、用量及步骤均保留，无桌面占用。
- 第一次反证：不再把combined、faithful-M1或定位反馈的无增益结果改名重试。
- 第二次反证：保持M3原预算、对照和候选都做相同消融；增加NF审计的等调用重抽和离线并集对照；不将确定性格式恢复当语义进步。
- 最后反证：实验后对全部输出审阅、区分机制初筛与端到端收益，检查负面结果和数据曝光。不根据结果改Prompt或重抽案例。

原正式blind-v2、作者裁定和生产接口不受本轮替代。小试仅能决定某机制是否值得扩大验证，不能直接支持上线或泛化宣称。
