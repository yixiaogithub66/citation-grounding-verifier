# 方法小试反证检查点 2

2026-10-23。对象为当前 `PLAN.md`、`pilot.py`、`test_pilot.py`、Gemini 第 2 轮意见、`judgment-cases.json`、`pilot-cases.json` 及原 v4 校验器。此检查未运行模型，未修改计划、代码、Prompt 或案例。**未发现阻断本轮有限小试的 critical 问题。** 结论只允许按已声明的阶段级诊断运行；不构成部署、泛化或作者终审批准。

利益/角色说明：本检查者就是 M1 合成案例的起草 AI，故对该文件的再读不是独立人类审核，也不是相互独立的标签生成。主代理另行逐条读了语义；两者仍都是 AI 交叉检查。M3 案例由另一工作分支起草。这里的独立性仅指与候选推理调用/其输出相隔离，不声称 AI 误差独立。

## 1. 当前 M3 strict validator 的实际边界

`validate_judgment()` 直接调用生产 `OptimizedV4Verifier._envelope()` 和 `_validate_row(..., review=True)`，未另写宽松判定器。固定目标只传 `c1` 与完整 `claim_text`，非 fallback，不能走 NF 排除。数组必须恰好一个目标；ID 与 claim 原文必须保持；U 不得保留非空公共引用；S/C 必须给可接受引文；C 在本次输出内必须通过 `conflict_error`。`review=True` 是为了当次强制 C 证据结构，没有调用复核模型，也不绕过 C/U 次数上限。

这是合理的单次初判质量门槛，但**不是原 v4 完整链路的等价执行**：当前初判可以先产生不合格 C，再进入既定 C 复核；小试将其当次记失败，没有复核或数值信号后的重判。PLAN 已说明阶段隔离，最终报告须继续称“单次初判通过率”，不要称“当前系统完整报告率”。

原安全格式修复被双方共同保留；内容差异通过 `_NeedsRequery` 报错，wrapper 不继续问模型。原始输出与修后输出分别保留，修复计数也保留。因此没有发现静默内容修复或格式失败转 U 的通道。

**必须坚持的语义边界：** 当前守卫检查字段、位置、引用包含关系和 conflict 锚点，不能判定“这段引文真的支持这个目标”。`test_judgment_safe_format_repair_not_content_repair` 中，“reading is 3.5”的 S 只引 `mode "amber"` 仍可结构通过，这恰好展示此边界，而不是测试应当变成语义分类器的理由。解释非空、冲突结构完整，也不能证明同主体/条件或充分推导。P1 必须逐条核对全部 48 次输出的证据与 derivation；不能以 `valid_and_label_hits` 替代预登记的“valid + 标签 + 证据/推导”分数。`analyze()` 将该语义工作留给后审、P2 `semantic_score:null`，目前做法符合边界。

无需增加代码语义规则来弥补这个限制。最小措施是最终报告分别列原始标签、结构合法、全分母语义正确，并在语义评分文件绑定原始输出；任何引用/推导错误即使标签碰巧正确也不能计入严格语义成功。

## 2. P2 并集、触发与 source-blind 边界

PLAN 已修正 Gemini 建议中的“按原答跨度去重”。相同跨度可能含多个事实，不同跨度也可能表达同一事实；当前方案按预声明的目标事实单元离线映射、每单元上限一次，并逐条保留错误新增。没有运行时合并，也没有把错误通过去重抹去。这比按输出 claim 条数计算恢复率更符合本项目契约。

四个比较必须原样保留：base；固定第二次输出的 fresh 替换；base+audit 离线可恢复集合；base+fresh 离线可恢复集合。只比较 audit 并集与 fresh 替换会偏袒 audit，当前方案没有这么做。基础失败不在 audit 链里偷偷缩小分母，fresh 成功可独立展示但不是 audit 成功；没有 NF 的输入只记未触发，不能假称执行一次审计得到“无漏提”。

审计仅收到原回答、带局部 ID 的排除文字及已提取的原答跨度。来源 context、初判理由、改写 claim、期望目标和禁提断言都没有进入 `audit_payload`。这维持了 source-blind：审计无法根据外部来源把原回答纠正成真话。已有跨度只用于给出提取位置提示，**不等于审计真正知道哪些命题已经提过**。提示自身已承认共享跨度不保证每个事实都提取；因此若重复建议了已有事实，应在离线评分记冗余而非新增恢复。

`validate_audit()` 只证明候选 span 精确位于被标识的 NF 文本内，并检查 schema、UTF-8 与完全重复行。它不证明候选是事实，不证明目标改写忠实，也不能捕获“保留了 source_span，却把条件删掉”的语义错误。后审要逐行检查 claim_text，不能仅看锚点合法。

这里仍有已声明的识别边界：一条混合句被 M1 错标为普通事实且完全没有 NF 时，P2不触发；已经提取但删掉限定的 claim 也不在本实验主要治疗范围。阴性结果不能直接否定全部事实覆盖审计方法，阳性结果也不能声称解决 M1 全部保真问题。

## 3. 数据与输入隔离核对

`inference_cases()` 白名单只保留固定 claim/context 或原回答；case ID 仅用于本地调度与记录，P1请求里的 `c1` 是统一目标索引。family、language、expected_verdict、expected_evidence、required_semantic_elements、forbidden_assertions、原始标签理由均不进入模型 payload。schema 数据是同进程读取的，但“进程能读到评估标签”不等于“模型收到标签”；当前白名单与测试足以支持这一窄输入隔离说法。

12 个 M3 条目的预声明标签在所给微型上下文下可解释：归属/方向的 C 有明确反证；温度范围扩大、原因新增与逆向全称推理没有直接反证，属于 U；唯一证据删除没有残留替代证据。这里只把它们视为 AI 草案诊断，不转为 RAGTruth 金标或作者裁定。

M1 的6个目标与6个纯NF也可按既定“步骤本身NF、明确事实前提保留”约定解释。纯建议中出现对象名并不机械追加“该对象现实存在”等断言。材料在当前候选Prompt与自然提取结果之前编写，未观察后挑选案例。计划规定全部运行且不后改标签，当前未见数据泄漏渠道。

## 4. 两项需收紧的描述，不要求改变冻结候选

### R1：配平只对 P1 成立

PLAN 顶层写“两臂先后配平”，而 `jobs()` 对 P1 逐例两次重复确实反转 base/candidate 顺序；P2 依赖性调度固定为 base→repeat→audit。该顺序适合先取得 NF 再审计，但并未对 repeat 与 audit 顺序配平。P2 的缓存、服务时间和时延比较可能因此受顺序影响。

最小修订是将计划/报告措辞收窄为“P1两臂先后配平；P2固定base、fresh、audit顺序，并报告实际缓存和统一未缓存费用”。不建议为此临时加调用、重排后再选择更好的时延数字。共同最多两次逻辑调用的比较也不等于 token 或实际费用相等，费用应继续全量记账。

### R2：P1 是提示强化，不是新架构的机制验证

`CANDIDATE_APPEND` 的主体、条件、范围、归属、同义和一步推导要求，原 `VERIFY_PROMPT` 已有大部分语义。新增的是更集中、临近判决的提醒，没有显式必要成分对象、独立搜索或第二判定器。因此可以检验“简短规则重述能否改善当前单次核查”，不能仅凭结果称实现了新颖的分解验证架构，也不能由解释中出现成分词推定模型确实按成分检查。

这不是禁止小试，也无需为了创新措辞强行加复杂协议。若两臂相同或满分，应报告没有区分度；若候选改善，应把原因表述为该提示干预的探索性效果，后续才有资格检验真正的中间表示/证据充分性分解。

## 5. 简单材料、统计与停止解释

短而明确的微型例适合发现条件、归属或NF边界的基本故障，但可能基线已经满分。特别是P2只有6个事实目标，A/B/C各用普通事实与建议版本复用同一内容；其余6条只测误事实化。它不覆盖长答案、跨块共指、自然格式失败、真实复杂含混或调用链效应。语言与家族混杂，不能用四种语言各三条宣称跨语言泛化。

P1两次重复共享同一案例，不能当24个独立语义样本；P2一次自然提取也不能估计稳定错误率。计划把门槛定义为工程筛选而非显著性，这应保留。Gemini 的“即被证伪”措辞应收窄为“在本批预登记条件下，不支持为该机制追加成本”；尤其基线全对时不能据零恢复否定NF审计的普遍价值。

通过规则比Gemini建议更严格：PLAN要求有效率不下降、NF新增误事实化为零，没有采纳“可容忍一条新增错误”的宽松替代。最终按PLAN执行，不在结果出来后切换到Gemini较宽门槛。即使全部通过，也只进入扩大验证，不进入生产。

## 检查结论

可按现有小试范围继续。没有必要改变当前模型或扩大重试；本检查建议的最小修订仅是明确 P1/P2 的顺序描述和 P1 方法命名。运行后优先逐条检查 P2 全部 base/fresh/audit 输出、冗余与错误候选，并把合法/完整与事实忠实性分别评分。生产、作者裁定、历史 benchmark 和正式未见集均继续隔离。
