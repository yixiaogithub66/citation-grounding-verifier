# 跨来源综合与可检验假设

状态：研究假设，尚未实现、尚未实测。研究日期 2026-10-23。本轮纳入 30 个一手来源：23 篇论文及 7 条官方工业资料；同一论文的不同版本不重复计数，工业资料也不作为独立实验计票。精确读取范围及限制见各 phase2 文件。

核心判断：优先研究“表示与职责分离”。让代码稳定保存文字身份，让模型判断命题及证据关系；分清待判目标、解释目标的背景、考察过的证据、最终对外引用。把更细拆分、更多复核或更高格式成功率直接等同于准确性，没有文献和本项目结果支持。

### 文献共同指出什么

- **提取和验证是不同的错误源。** Claimify 将蕴含、覆盖、去语境化拆开评价；DecompScore 用原回答检查提取是否忠实；DnDScore 将核查目标与理解背景区分。它们共同支持分开诊断，不证明某个拆分器已经适合我们的全部输入。[Claimify](https://aclanthology.org/2025.acl-long.348/) [DecompScore](https://aclanthology.org/2024.starsem-1.13/) [DnDScore](https://aclanthology.org/2025.emnlp-main.1205/)
- **更细不必然更好。** Decomposition Dilemmas 和 MiniCheck 的具体实验出现拆分改善与退步；删除限定或制造碎片的风险是真实的，原子化应保持完整独立断言。[Dilemmas](https://aclanthology.org/2025.naacl-long.320/) [MiniCheck](https://aclanthology.org/2024.emnlp-main.499/)
- **出处有效与证据充分是不同保证。** GAVEL 将两者分层；Anthropic 的原生citation文档也限定指针保证；Google明确结构化输出不保证语义。[GAVEL](https://aclanthology.org/2026.findings-acl.1789/) [Citations](https://platform.claude.com/docs/en/build-with-claude/citations) [Structured outputs](https://ai.google.dev/gemini-api/docs/structured-output)
- **复核需新信息视图和净收益审计。** CoVe/MARCH提供信息隔离的动机；自纠错反证与RT4CHART（2026预印本）的分集合结果说明重复判断也会改错或没有收益。模型调用分开不代表统计独立。[CoVe](https://aclanthology.org/2024.findings-acl.212/) [MARCH](https://aclanthology.org/2026.acl-long.1828/) [Self-correction study](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html) [RT4CHART](https://arxiv.org/html/2603.27752v1)

## H1：以不可变文字单元为定位基础，分离待判目标与解释背景

**联合来源：** Claimify、DnDScore、DecompScore、HFH，以及工业上下文工程的职责分离经验。[HFH](https://aclanthology.org/2026.findings-eacl.46/) [Context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

待验证机制：

1. 代码为答案中的原始文本单元分配稳定ID和字符区间，完整保留原始文字；单元是定位容器，不声称已经完成原子化。
2. M1输出完整原子命题、对应答案单元/必要跨度，以及用于指代、列表范围、时间和归属解释的答案背景引用。一个命题可关联多个原始单元，由M1在必要邻域、标题和列表前言可见时统一抽取；无法恢复依赖则保留未决。单元内保留已映射跨度和残留跨度，允许事实、非事实、歧义和未处理内容混合存在，不能以“该单元访问过”代替全部处理。
3. 背景属于“待核查回答的一部分”，不属于支持证据；不得用来源context纠正M1正在抽取的错误答案，也不得将背景中的附加事实当作已核实前提。必要限定仍是目标命题的判决条件，不能因移入背景字段而被弱化或忽略。
4. 对未覆盖内容做有界的M1补提取或保留显式降级，而非为了完成覆盖把其余内容全部列为非事实。粒度仍归M1，任何共享背景不构成运行时拼句/语义合并。
5. 区分文字记账和语义覆盖：ID覆盖只检查是否处理过对应单元；用固定事实金标另外评价遗漏、虚构、加强、限定丢失及过切。

**预期而非已证：** 降低模型重复抄写的负担，并让遗漏定位更清楚。先测试仅改变定位协议的H1a，再测试目标/背景分离与残留审查的H1b，避免把语义收益归给格式变更。

**主要反证：** 模型可能给整句挂一个ID但仍漏一半事实；单元边界可能切断列表前言、公式、代码或指代；更多字段可能增加tokens。若格式通过率升而事实覆盖下降，就否决该变体，不能称“修复67个问题”。

## H2：把考察证据与对外引用分开，用位置选择代替自由抄写

**联合来源：** GAVEL的证据绑定、原生citation的位置设计、结构化输出边界、RT4CHART的来源回映。本项目日志提供U附引文反复触发重问这一工程观察。

建议研究新的内部协议，而非修改公开 `/verify` 契约：

- 原文context采用稳定的证据单元ID，保留原始段落index、字符区间、父级和必要邻域。模型选择位置，程序从原始字符串生成精确quote。
- 新内部协议须版本化并按标签区分字段：`considered_evidence_ids` 表示模型声明考察过的候选证据，并不证明它实际充分检查。S/C必须另有承担结论的 `decision_evidence_ids`；U可记录缺失前提和考察候选，但结论证据字段必须为空。U若给非空结论证据仍报错，不能简单改字段名称掩盖原问题。公共citations是通过校验后内部对象的契约投影，U输出[]。
- 代码验证所有ID存在、没有跨来源串错、区间有效和公共引文逐字一致。模型仍负责判断证据是否共同支持完整命题。C保留既有冲突契约：同对象、同条件的直接冲突，或以齐全引用前提展示契约允许的一步推导/计算冲突；不借此引入代码算术求解或单位换算。
- 不采用“接到旧格式非法citations后直接删掉”的补丁。新协议从定义上分离考察证据和公共引用；未知ID、坏引用或执行失败仍是错误，不能靠序列化变成U。
- 对答案自身声称“某来源说X”的内容，保留被声称的来源范围；在另一段找到X，不自动证明原归属正确。
- 候选位置选择不等于语义通过，且不能因top-k未命中直接给U。短context继续全量读取；如果研究长context候选检索，U必须保留全量输入回查路径，但全量输入不证明语义搜索穷尽。跨段共同前提不得被单块max分数替代，推导仍受既有明确一步推理契约约束。内部协议变化不能取消U的既有复核资格，也不证明151次重问都能被删除。

**可拆消融：** H2a只分离内部考察证据/结论引用，定位仍使用当前index/quote形式，字段用considered_evidence与decision_evidence；H2b才将这两类位置改成ID选择并由代码回填。H2c仅在同一次初判请求/响应内要求检查完整前提/限定，不另起审核调用。分别对直接前置对照测量，避免混淆格式、定位、语义和额外调用收益。

**主要反证：** 模型可能选择有效却无关的ID，或引整段掩盖缺少关键前提；U的空公共引文仍可能隐藏错判。须保留内部轨迹并独立审计语义。Anthropic当前原生citations与严格structured outputs存在兼容限制，跨供应商方案应采用自己的中间协议与能力适配，不能假设所有API组合可用。

## H3：在现有复核上限内检验“初判盲化”的证据重查

**联合来源：** CoVe、MARCH的信息隔离；QAFactEval的QA视角背景；RT4CHART的全局重查；Huang等的正确改错反证。QAFactEval本次只读摘要，不以其数字或组件细节作为实现论据。

研究两种统一复核输入：A为现有复核，B在必要的C/U复核中不展示初判标签、理由和已选择引文，只接收原claim、必要的目标范围和完整原始context，在现有一次复核请求/响应内重新输出证据与S/C/U。原claim仍可见，因此只称“初判盲化”，不声称实现MARCH中连候选答案也隐藏的强盲化。若以后研究先独立问答、再语义对照的两调用方案，那是另外的预算/机制实验，不混入本轮H3。

保留现有触发条件（包括数值冲突信号可从初判S触发C复核）、C后U的顺序、总C复核≤1、U复核≤1，以及U→C必须同次给合格conflict的约束。格式重试按既有配置计数，全链仍只共享一次targeted quote requery，不为每阶段重开额度；不新增无限辩论或普遍S复核。未触发复核的S等项目可在离线评测中抽样审计，以量化触发机制漏过的问题。

**主要反证：** 问题可能暗示答案或丢失否定/范围；同模型同context依然共享错误；按U触发也泄露选择信息。需与“同预算再调用一次相同策略”对比，并统计错→对、对→错、未变、执行失败及额外耗时。净修正 = 错→对 − 对→错，39次翻转不是39次正确修复。

## H4：用离线行为与变形测试验证规则是否跨表述成立

**联合来源：** CheckList的行为矩阵、FactCG的必要证据删除诊断、HFH的参数知识干扰测试、FaithBench的灰区与选择偏差、工业eval轨迹审计。[CheckList](https://aclanthology.org/2020.acl-main.442/) [FactCG](https://aclanthology.org/2025.naacl-long.258/) [FaithBench](https://aclanthology.org/2025.naacl-short.38/) [Evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

离线测试族：

| 变化 | 预期关系 | 前置条件 |
| --- | --- | --- |
| 一致替换实体名、保义改述 | 标签保持 | 无实体碰撞、无新增背景含义；先审核保义 |
| 调整证据顺序 | 判决保持、引用位置相应变化 | 若答案提到“第2段”，必须同步维护来源身份，不能直接当不变测试 |
| 加入无关材料 | 判决保持 | 新材料真的无关且不构成额外支持/反证 |
| 删除唯一必要前提 | S→U | 确保所有替代证据均不存在，且未留下反证；不满足这些前提的变体不归入此测试族 |
| 改同对象同单位的数值、极性或限定 | 期望改变或缺证 | 不能预设所有微改动都必须S→C；按完整语义构造明确期望 |
| 分割支持前提到不同段落 | 共同充分性保持 | 不改变关系、指代或数据语义；仍满足既有一步推导契约 |
| 调整答案侧定位单元边界 | 提取的命题与必要限定保持 | 原答案不变，M1仍看得到跨单元依赖，专门测试H1而非只测M3 |
| 输入与模型常识冲突 | M1保留待核查答案；M3依给定证据判断 | 两种文字职责不同；答案与证据冲突仍应判C，忠实提取不等于事实受支持 |

这些是诊断方法，不是生产多次投票，也不能证明稳定输出一定正确。同时报告关系符合率和具有可靠标签的原/变体双项正确率；不清楚保义或方向的AI草案只作探索性诊断。AI生成的变体保留草案身份；测试模板不进入推理Prompt或规则。预先固定开发/保留的变形家族，避免在同一组模板上反复挑选最有利版本。

## 为什么不是照搬一种方法

| 近邻 | 借鉴的机制 | 本项目不能原样采用的部分 |
| --- | --- | --- |
| Claimify / DnDScore | 事实筛选、目标/上下文分离、分维评价 | Claimify不解歧义时可能整句排除；DnD条件样本结果不保证完整覆盖 |
| FActScore / SAFE / VeriScore | 原子事实、分阶段评价 | 外部搜索事实性不等于给定context忠实性；不照搬搜索来源或benchmark演示 |
| GAVEL / RT4CHART | 证据单位、确定性定位、完整证据与全局重查 | 已有近邻，不能把同样结构重命名宣称首次；多代理或多轮不直接装入既有预算 |
| CoVe / MARCH | 隔离初判影响、改变证据视图 | 训练/生成结果不证明API级盲化收益；不同角色不是独立错误 |
| MiniCheck / AlignScore | 可作为低成本影子信号的候选 | 标量或二分类不能直接恢复C/U；短块max/全文mean可能与任务聚合不同 |
| FactCG | 多前提与证据删除诊断 | 主结果逐数据集阈值调优不适用本项目，不能直接移植其分数优势 |
| FaithJudge | 标注口径透明、多集合比较 | 运行时使用同来源人工标注回答，不符合当前禁止benchmark特调的约束 |

**创新定位：** 现有工作已覆盖分解、证据绑定、三标签和复核。可研究的组合是：在固定HTTP契约和调用上限内，同时将答案侧覆盖记账、目标/背景分离、证据侧指针、内部考察证据与公共引用分离，并审计每次修复的净语义收益。它是本项目待验证的工程组合假设，不是已证实的学术首创。需要通过相对单模块和等成本对照证明其增量价值。

## 逐步验证协议

1. **先固定评价对象。** M1用完整事实清单测覆盖、提取忠实性、限定/归属保留、NF误排除与粒度；现有341条举报裁定不等于完整事实清单。M3用固定claims分别测S/C/U和证据共同充分性；端到端继续测回答FP/FN、部分完成、未知项与成本。
2. **先工程变量，再语义变量。** 当前v4作为共同base，H1a和H2a分别单独对base；H1a固定原分块器、输入文字及预算，避免混入重分块收益。H1b再把目标/背景分离与残留审查拆成相对H1a的独立消融，最后测组合。H2b对H2a，H2c对H2b，主效应只在各自前置条件下解释，另外预先指定组合，不将累计变体的差值冒充独立因果效应。H3先固定同一初始轨迹/触发集合和预算，再测端到端触发分布变化；等调用数不足以表示等成本，还要比较输入/缓存输入/输出tokens、统一计价和延迟。
3. **完整报告分母。** 命题覆盖、已完成项准确率、精确引用、证据语义充分性、整例判定与操作失败各自有分母。CPHOS严格文本对齐降低不能单独等同语义退步；也不能只展示已对齐项准确率掩盖遗漏。
4. **来源级与跨任务检查。** 开发集仅作诊断，统一配置，不按dataset/ID/生成器切换。对预先规定的小规模分层样本重复运行测波动，按来源组给区间；不把同源多个回答当独立样本。
5. **冻结后未见检验。** RAGTruth v2仍按既定先冻结后取数协议，研究示例曝光先核实并排除对应来源；正式测试前不得预读样本。独立外部集合先固定标签映射与采样，不把FaithBench的benign/questionable直接硬映为S/C/U。v2同数据家族仅支持未见来源外推，不能独自证明跨数据集泛化。
6. **失败条件明确。** 格式改善但事实召回下降、C精度下降、复核净改错、引用更长却缺少前提、或成本上涨无稳定语义收益，是应否决的机制失败信号。正式实验冻结前还须登记主要指标、非劣界限、区间/重复规则和成本上限；不能把有限样本的任意点估计波动事后解释为通过或失败。本报告是研究路线，不冒充已经完成这些数值决策的冻结协议。此前作者验收目标保留，不能用调标签或丢弃未完成项制造达标。

## 建议优先级

P0：评价隔离和H1a/H2a协议实验；P1：H1b/H2b及完整前提审核；P2：H3盲化复核；P3：有充分校准后才考虑小模型影子信号或路由。H4从第一阶段伴随开发。当前不建议先引入更长Prompt、全量多代理辩论、开放网络补证、运行时图谱/合并或按benchmark阈值优化。

本轮没有新模型实验，不能给出预期百分点或宣称将达到FN=0。人工裁定剩余细节按用户要求暂缓；研究和协议设计可以先推进，正式裁定口径验收仍需其版本完成。
